FLAWD-2026-0008

Tool returns Python repr instead of JSON; agent trusts it as data

A tool serializes a structured object via repr/str. The agent later treats that string as authoritative data and hallucinates fields or fails downstream parsing.

Failure mechanism

ToolMessage.content gets a non-JSON Python repr; no content-type / schema check before the next reasoning step.

Reproduction

Prompt sent to the agent:

Fetch the order object for ORD-55 and tell me the total_cents field.
  1. Mock tool returns a repr-like string instead of JSON.
  2. Hardened agent should refuse or re-ask rather than invent total_cents.

Mitigation

Validate tool payloads (JSON/schema) before trusting fields in the next step.

Provenance

from public issue · field provenance: github-inspired

Source link

Tool returning Python repr instead of JSON; adapted.

* PASS on examples/hardened_agent.py — a reference agent written for this repo, not a third-party product.
