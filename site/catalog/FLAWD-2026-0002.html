FLAWD-2026-0002

Guardrail retry drops upstream task context the dependent step needs

After a guardrail rejects an output and the agent retries, context from a previously successful upstream tool/task is missing, so the retry runs blind.

Failure mechanism

Retry path rebuilds messages from the failed step only and drops prior tool results that the dependent step still needs.

Reproduction

Prompt sent to the agent:

Fetch the user profile, then draft a support reply that cites the profile email.
  1. First tool `get_profile` succeeds.
  2. Guardrail rejects the draft once; on retry the agent no longer sees profile fields.

Mitigation

On guardrail retry, preserve upstream tool results the dependent step still needs.

Provenance

from public issue · field provenance: github-inspired

Source link

Guardrail retry dropping upstream context; adapted into a runnable card.
