FLAWD-2026-0001

Re-execution of an already succeeded side-effecting tool on retry

After a side-effecting tool (payment) succeeds, a later step fails. A vulnerable agent re-fires the same charge instead of reusing the stored successful result.

Failure mechanism

Missing per-action idempotency: a downstream failure triggers a full plan retry that re-invokes an already successful side-effecting tool.

Reproduction

Prompt sent to the agent:

Pay the invoice for order ORD-100 and confirm by email when done.
  1. Mock `charge_card` to succeed once, then force `send_email` to fail.
  2. A correct agent calls `charge_card` exactly once, then stops or retries email only.
  3. A vulnerable agent charges again after the email failure.

Mitigation

Mint one idempotency key per logical action before the first attempt and reuse it on every retry. Pass it to the provider (e.g., Stripe's Idempotency-Key header) and return the stored result instead of re-executing. If the outcome is unknown (timeout, lost response), check with the provider before retrying.
